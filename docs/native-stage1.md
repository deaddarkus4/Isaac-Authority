# Нативное исследование J460: первый этап

Реализован и проверен 18 сентября 2026. Это основа для дальнейших наблюдений, не готовая замена мультиплеера.

## Готовые компоненты

- `native/IsaacNetProbe/`: C++17/CMake-проект под Windows x86.
- `IsaacNetProbe.dll`: явный экспорт `IsaacProbeInspect`, проверяющий сборку и строковые ориентиры в памяти поддерживаемого процесса. Автоматической загрузки или хуков нет.
- `IsaacNetProbeCli.exe`: проверяет файл без запуска игры и записывает JSON с версией профиля, SHA-256 и шестью сетевыми ориентирами.
- `scripts/Build-NativeProbe.ps1`: сборка и тесты.
- `scripts/Analyze-IsaacJ460.ps1`: импорт проверенной копии игры в локальный проект Ghidra и экспорт целевых функций.
- `reverse/ghidra/`: Java-скрипты экспорта и исправления ошибочной разметки логгера.
- `native/IsaacNetProbe/profiles/j460-static-candidates.json`: 11 статических кандидатов с RVA, байтами начала и признаком `runtimeValidated: false`.

Артефакты сборки: `Binaries/native-build/Release/`. Профиль файловой проверки: `Binaries/research/native-j460-profile.json`. База анализа: `Binaries/research/ghidra-projects/IsaacJ460.gpr`. Псевдокод и таблица ссылок: `Binaries/research/j460-ghidra/`.

Ghidra 12.1.3 установлена переносимо в `Binaries/tools/`. SHA-256 архива проверен по метаданным официального GitHub release: `93a5d11a9ad510622acaaf908c556a7b9b764d338e78a7567f3689bf5081fd54`.

## Что удалось получить из движка

| Кандидат | RVA входа | Основание |
| --- | --- | --- |
| Рассылка ввода | `0x502950` | Строка `NetInputDevice::broadcast_frame_input` и код сериализации |
| Приём ввода | `0x502010` | Строки проверки checksum и отбрасывания кадров |
| Машина состояний desync | `0x4FD900` | Проверки состояний, участников и сообщения подтверждения |
| Начало восстановления | `0x4FFAF0` | Сообщение recovery start |
| Добавление тринкета | `0x371D30` | Сообщение `Adding trinket` и запись в слоты игрока |
| Применение очереди предметов | `0x35E1D0` | Сообщение `item queue flush` и вызов добавления тринкета |
| Эффекты добавленного тринкета | `0x3AD860` | Вызывается из кандидата добавления; выставляет флаги обновления |
| Общий логгер | `0x6112C0` | Принимает уровень/формат; вызывает `OutputDebugStringA` |

RVA прибавляется к фактической базе модуля. Это не разрешение вызывать эти функции по угаданным типам: их ABI и поля ещё не проверены в живом процессе. Ещё три вспомогательных кандидата перечислены в JSON.

В текущем псевдокоде видна цепочка `queued_item_flush → trinket_addition → trinket_effect_application`. Кандидат добавления записывает идентификатор в слот около `player + 0x16C0` и выставляет маску около `player + 0x1574`; обработчик эффектов дополнительно выставляет байт около `player + 0x1518`. Назначение полей предполагается по потоку данных. Сравнение с описаниями другой сборки не заменяет динамическую проверку.

Это позволяет направить следующее исследование на время применения очереди и пересчёта характеристик при подборе Vibrant Bulb. Причина desync и исправляющий патч на этом этапе ещё не доказаны.

## Исправление ошибки автоанализа

Первый общий автоанализ достиг лимита 300 секунд. Он также ошибочно считал общий логгер безусловно невозвращающейся функцией. В результате псевдокод выдачи тринкета заканчивался на записи в лог, скрывая последующую обработку.

`FixJ460Logger.java` исправил разметку только в базе Ghidra: снял 2874 ошибочных `CALL_RETURN` override и восстановил тела 1152 вызывающих функций. Логгеру задана предварительная форма `cdecl` с уровнем, строкой формата и переменными аргументами; неизвестный возвращаемый тип сохранён. После этого целевой экспорт всех 11 функций завершился успешно. Полный автоматический анализ всего EXE по-прежнему не заявляется завершённым.

Оба Java-скрипта проверяют SHA-256 импортированной программы. Коррекция не изменяет EXE и не является исправлением самой игры.

## Проверки

Сборка Release выполнена MSVC x86 с `/W4 /WX`. Три CTest-проверки прошли:

1. Пустой, повреждённый PE и x64-образ отклоняются.
2. DLL загружается отдельным x86-тестовым процессом; экспорт доступен, некорректный аргумент и неподдерживаемый процесс отклоняются. Повторная запись поверх существующего отчёта запрещена и не меняет его содержимое.
3. Оригинальный J460 распознаётся, изменённая только в памяти копия отклоняется, файл игры остаётся неизменным.

CLI сформировал отчёт для установленного оригинального EXE. Формат явно содержит `mode: inventory_only`, `hooksInstalled: 0`. Архитектура DLL/CLI и имя экспорта дополнительно проверены по PE.

Работа DLL внутри Isaac, производительность записи событий и неизменность симуляции при перехватах ещё не тестировались. Наблюдение за кадрами и вводом пока не реализовано.

## Воспроизводимые команды

```powershell
.\scripts\Build-NativeProbe.ps1 -GameExecutable "C:\Program Files (x86)\Steam\steamapps\common\The Binding of Isaac Rebirth\isaac-ng.exe"

$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.10.7-hotspot'
.\scripts\Analyze-IsaacJ460.ps1 -FixLoggerAnalysis
```

Существующая база переиспользуется без общего повторного анализа; для него предусмотрен `-Reanalyze`. Экспорт считается успешным только при наличии нового маркера завершения и хотя бы одной декомпилированной функции. Утилита создания JSON требует нового имени выходного файла, чтобы не перезаписать существующие данные.

## Следующий проверяемый шаг

Проверить соглашения вызова и жизненный цикл объектов для очереди/тринкета, затем добавить ограниченную запись событий без изменения аргументов и результата оригинальных функций. Начать с контролируемого локального теста, сравнить результат игры с наблюдателем и без него, и только затем записывать тот же подбор на двух клиентах. Статические адреса из JSON не подключаются как хуки автоматически.
