# Общее сохранение: одинаковые уровни в двух играх

**20 сентября 2026, 00:06–00:13 UTC.** Пользователь заметил: на одном и том же seed в окне HOST есть проклятие, а на чистом сохранении — нет. Раньше проект уже знал, что при одном seed различаются 5 комнат из 15, и обходил это сверкой каждой комнаты маршрута. Это расхождение самого мира, сверкой состояний оно не лечится. [Штатный онлайн](j460-online-path-research.md) решает его общим сохранением; здесь причина доказана и устранена тем же способом.

## Причина: сохранение, и только оно

Третий изолированный экземпляр запущен с **копией сохранения основной игры**; HOST и прежняя REPLICA не трогались. Во всех трёх играх один seed `CZH4 8E6W`, персонаж Isaac, сложность hard. Чтение памяти, без вмешательства:

| | HOST | REPLICA, чистое сохранение | Третий экземпляр, копия сохранения HOST |
| --- | --- | --- | --- |
| Сохранение слота 1 | 8412 байт, прогресс «The End» | 4068 байт, пустое | та же копия, SHA256 `839b891e…` |
| Сложность (`Game+0x269c8`) | hard | hard | hard |
| Проклятия уровня (`Game+0xc`) | **Darkness** | нет | **Darkness** |
| Комнат уровня | 15 | 15 | 15 |
| Комнат, отличных от HOST | — | **5** (83, 85, 109, 126, 138) | **0** |
| Общие с HOST двери стартовой комнаты | — | вниз (97) | вправо (85) и вниз (97) |

Исключено проверкой: **моды** — все 11 отключены (`disable.it`) и комнат не добавляют, набор папок у экземпляров отличается только пользовательской `upgrader`; **сложность** — одинаковая. Генерация уровня читает то, что открыто в сохранении: от этого зависят и наборы комнат, и проклятия.

После рестарта забега клавишей R совпадение сохраняется (seed введён вручную и переживает рестарт).

## Что это дало сразу

Живой тест перехода с коррекцией врагов (`Test-IsaacRoom.py --stage npc --route door --direction right`) прошёл **через правую дверь в комнату 85** — раньше она различалась и была тестам недоступна: 7 врагов у хоста, 7 сопоставлены во всех 208 кадрах, лишних и несопоставленных 0, 2240 коррекций, состояния побитово равны хосту, слоты восстановлены. Первая попытка оборвалась на второй секунде потерей фокуса окна, до начала движения; повтор прошёл. В конце внешнее чтение двух игр дало расстояние между одноимёнными врагами до 3,5 единицы: враги в этой комнате подвижные, а два процесса читаются не одновременно (у неподвижных червей прежних прогонов было 0,0). Summary: `npc-20260920-001232-732906` в `Binaries/diagnostics/npc/`.

`isaac_level.snapshot` теперь читает сложность и проклятия, и `--check` считает их расхождение проблемой: прежняя REPLICA отвергается с «curses: 1 != 0», экземпляр с общим сохранением проходит.

## Как это сделано сейчас: копия сохранения при запуске клиента

`scripts/Start-IsaacReplica.ps1 -PersistentGameData <файл>` кладёт копию файла в новый изолированный профиль как слот 1 и только потом запускает игру. Игра загружает его собственным штатным загрузчиком — никакого реверса формата.

- **Сохранение пользователя только читается.** У основной игры `SteamCloud=1`, файл — `Steam\userdata\<id>\250900\remote\rep+persistentgamedata1.dat`; локально тот же формат называется `persistentgamedata1.dat` (заголовок `ISAACNGSAVE09R  ` проверяется). Хеш облачного файла до и после запуска совпал.
- **Копия никуда не уходит:** профиль экземпляра отдельный, `SteamCloud=0`. В забеге с введённым seed игра сама ставит сохранению «только чтение» (`Manager+0x15 = 1` у всех трёх игр), так что копия в таком забеге ничего не открывает.
- Это и есть осмысленная схема входа клиента для прототипа: клиенту всё равно нужен изолированный экземпляр, и он получает сохранение хоста до запуска. Недостаток — нельзя войти, не перезапуская игру.

Ввод seed остаётся ручным шагом, но теперь выполняется проектным помощником с защитой фокуса (клавиши уходят только окну нужного процесса) и снимком окна после каждого шага: Enter (заставка) → Enter (титул) → Space (слот 1; кнопка «Delete file» не выбирается) → Enter (New Run; пункт Online не трогается) → Tab → восемь символов seed → Enter → Enter. Сложность на экране выбора персонажа берётся из сохранения — с копией она совпадает с хостом сама.

~~Вывод по штатной схеме: сохранение одного участника рассылается всем.~~ **Этот вывод был неверен** — поправка пользователя, знающего штатный онлайн из первых рук: общее сохранение — не чьё-то одно, а **пересечение по всем участникам**. Предмет или босс, не открытый хотя бы у одного игрока, не появляется ни у кого; так же подстраиваются уровень магазина и число пожертвованных монет. Это объясняет и четыре `Shared save user ID` в отчёте о десинке. Остальное в силе: общее сохранение грузится во встроенный `PersistentGameData`, на время матча он «только для чтения», его контрольная сумма сверяется каждый кадр. См. [сохранение лобби](j460-lobby-save.md).

## Дальше

- **Прежняя REPLICA (PID 12800, чистое сохранение) для тестов мира больше не годится** — `--check` её отвергает. Экземпляр с общим сохранением (PID 39920, окно «Isaac Authority - SHARED SAVE») заменяет её в обеих ролях. Закрыть старое окно — решение пользователя; проект чужие игры не завершает.
- **Вход без перезапуска** — загрузка сохранения хоста во встроенный `PersistentGameData` во время работы: найти разбор сохранения из буфера и безопасную точку вызова. Нужен, только если файловой схемы окажется мало.
- **Согласование seed без ручного ввода** и передача полного состояния — следующий шаг «как у штатного онлайна»: клиент входит в забег хоста, а не начинает свой с тем же seed. Отправные точки: `0x2f6500` принимает указатель и размер — вероятно, загрузка состояния забега из сетевого буфера (что именно она разбирает, не выяснено); `Game::RestoreState(GameState*, bool)` по сигнатуре REPENTOGON находится в J460 однозначно, RVA `0x2bb790`, `GameState::write` — `0x5c9340`; `Game::SaveState` неоднозначен (`0x2f9000` и `0x512b60`), `Game::NetStart` по сигнатуре не находится. Ни одна из этих функций не вызывалась.
- Общее сохранение не отменяет остальных ограничений: одна машина, транспорт — тест.
