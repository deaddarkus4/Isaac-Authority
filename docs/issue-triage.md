## Focused EID checks

An isolated .NET 8 console harness compiled the current `EIDPatcher.cs` and tested four temporary Lua files. Both exact legacy guards from v1.3.1's `oldPatches` were incorrectly reported as `Patched`; `Patch()` returned `false` and left their SHA-256 unchanged, including the obsolete `EID.isOnlineMultiplayer` condition. The current guard was correctly left alone, and an unpatched block transitioned from `NotPatched` to `Patched` with a no-op second application. This confirms a recognition/migration defect without running the game.

Current EID source was also checked at commit `3b5010128a8b38c2ca02c66441ddf8b8d8f10de3`:

- [Reminder settings](https://github.com/wofsauge/External-Item-Descriptions/blob/3b5010128a8b38c2ca02c66441ddf8b8d8f10de3/eid_config.lua#L337) still include `ItemReminderDisableInputs` (default `false`) and the reminder action setting. Before a run, setting **Reminder → Hold to Show = Drop** and keeping **Disable Player Inputs = Off** is a practical workaround to test for #14.
- [Crafting search](https://github.com/wofsauge/External-Item-Descriptions/blob/3b5010128a8b38c2ca02c66441ddf8b8d8f10de3/features/eid_bagofcrafting_search.lua#L367) blocks input independently of the reminder setting. Thus turning reminder input blocking off does not solve #7. A restrictive online configuration could disable the **Crafting → Search (Keyboard only)** hotkey; making text search work online requires a separate synchronization investigation. The [MCM hotkey implementation](https://github.com/wofsauge/External-Item-Descriptions/blob/3b5010128a8b38c2ca02c66441ddf8b8d8f10de3/features/eid_mcm.lua#L221) supports clearing a hotkey.

## Additional defects found while checking the issues

These are code findings, not established causes of every issue linked above.

- `MainWindow.xaml.cs:45–46` saves the co-op patch before attempting analytics. If analytics is unsupported, an error leaves co-op applied. Validate both replacements in memory and save once; expose the analytics status. Test that an unsupported second patch leaves the file unchanged.
- `GamePatcher.cs:175–191` returns `Unsupported` for a mixture of known original and patched character regions. `PartiallyPatched` is declared and displayed but never returned. A supported mixed state can be reported separately and completed or reversed after validating every region; genuinely unknown or ambiguous states must still be rejected.
- `MainWindow.xaml.cs:138–154` finds EID by directory-name fragments and one file. A manual mod-directory option and clearer identification could improve diagnosis, but this is not evidence that a particular report was caused by path detection.

## Antivirus reports

[#1](https://github.com/xADDBx/Isaac-Online-Modded/issues/1), [#18](https://github.com/xADDBx/Isaac-Online-Modded/issues/18), [#22](https://github.com/xADDBx/Isaac-Online-Modded/issues/22), and [#23](https://github.com/xADDBx/Isaac-Online-Modded/issues/23) concern detections or alleged malware. The maintainer attributes detections to executable patching and points to the build workflow. That explanation alone does not independently verify a downloaded sample.

Practical improvements here are release checksums and build provenance, a documented source-build path, and potentially signing official artifacts. These improve verification; they cannot guarantee that every antivirus stops flagging the program. Disabling antivirus is not a software fix.

## Review limits

The source and all issue discussions were read, and the EID migration behavior was reproduced with temporary fixtures. Multiplayer sessions were not run. User-attached crash/desync archives and antivirus samples were not downloaded or independently verified. A closed issue can represent a workaround, unsupported request, or missing reproduction rather than a code fix.
