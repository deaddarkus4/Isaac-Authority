# Смена курса: взять онлайн самой игры и заменить в нём только синхронизацию

**20 сентября 2026.** Предложение пользователя после [процесса лобби](j460-lobby-process.md): не строить рядом с игрой собственные лобби, транспорт и создание игроков, а использовать штатные компоненты — «даже тот же мультиплеер, просто изменить в ключевых функциях логику сети». Документ фиксирует, что для этого уже известно из бинарника J460 (только статический разбор, игра не запускалась) и какой план из этого следует. Результаты Ghidra — `Binaries/research/j460-net-service*`, `j460-lockstep-*` (в git не входят).

## Что решил пользователь

- **Модель доверия.** Авторитет хоста — только над миром: положения, события и тому подобное. Статусы, статы, предметы своего персонажа считает его владелец, остальные ему доверяют; считать это отдельно на хосте «пока муторно».
- **Что болит.** Десинк — худшее; задержка ввода отдельно выводит из себя.
- **Как ведёт себя штатное восстановление** (со слов пользователя, из первых рук): игрока выбрасывает из лобби в собственное лобби — либо вдвоём с кем-то из друзей, то есть компанию может разделить пополам; он остаётся в том же месте с теми же вещами, но без друзей. Это раскол сессии, а не синхронизация, поэтому опираться на него как на «хост всегда прав» нельзя.

Следствие модели доверия: свой персонаж авторитетен у себя, значит **предсказание и сверка своего игрока не нужны**, а задержка ввода исчезает по построению — ввод применяется сразу, хост его не пересчитывает.

## Что найдено в игре

### Сетевой сервис выбирается фабрикой, и локальный сервис в ней есть

Фабрика — RVA `0x629370`, текущий сервис — глобальный указатель RVA `0x879a58`:

| Аргумент | Сервис | Таблица методов (RVA) |
| --- | --- | --- |
| 0 | нет | — |
| 1 | `KAGE::Network::Multiplayer::ServiceLocalhost` | `0x7a23a4`; лобби `LobbyLocalhost` `0x7a8330`, соединение `ConnectionLocalhost` `0x7a839c` |
| 2 | `ServiceSteam` | `0x7a2440` |
| 3 | EOS | `0x7a2530` |

Локальный сервис — полноценный код: при создании разрешает окну сообщение `0x4a` (`WM_COPYDATA`), то есть экземпляры игры на одной машине разговаривают оконными сообщениями, без Steam. **Ни один из девяти вызовов фабрики не передаёт 1**: все выбирают между 2 и 3 по полю платформы `Manager+0x2a3fc`. Похоже на стенд разработчиков, оставленный в релизе; ключ `--localhost_match`, который лишь разводит журналы экземпляров по файлам, по всей видимости сделан для него же *(вывод, не факт)*. Работает ли локальное лобби до конца, неизвестно: в бинарнике есть строка `Localhost lobby values currently not supported`.

Если это заработает, снимается главная причина, по которой проект шёл снаружи игры: штатный онлайн негде было проверять — два экземпляра под одним аккаунтом Steam друг с другом не играют.

### Ядро lockstep

| Что | Где (RVA) | Что делает |
| --- | --- | --- |
| Ворота кадра | `0x510980`, метод сетевого менеджера; текущий кадр — `менеджер+0xc` | обходит все сетевые устройства ввода (`0x501cb0` — «готово ли устройство к этому кадру») и очереди событий, назначенных на кадр; пока хоть одно не готово, возвращает 0 и кадр не считается. **Это и есть ожидание самого медленного и источник задержки ввода** |
| Приём ввода | `NetInputDevice::ProcessInputMessage` `0x502010` | пакет: контрольная сумма (та же затравка `0xFEDCBA76`, что у сохранений), 12 байт заголовка, номер кадра, 16 байт записи ввода; кадры раньше `Manager+0x4b3e4` и уже имеющиеся отбрасываются. `CHECKSUM MISMATCH` здесь — целостность пакета, не состояние игры |
| Есть ли ввод кадра | `0x501190` | вызывается воротами, приёмом и ещё двумя функциями |
| Автомат десинка | `0x4fd900` | `Recovery Start`, `Desync Handler creating new lobby` — тот самый раскол лобби |
| Задержка ввода | `0x524440`, `0x524d10` | чтение и запись настройки `OnlineInputDelay` |
| Уже разобрано раньше | [сохранение лобби](j460-lobby-save.md) | сбор общего сохранения, рассылка при старте, наложение поверх своего, обратная запись |

## План

Штатное остаётся как есть: лобби и его интерфейс, общее сохранение, синхронный старт, создание игроков из состава лобби, сетевые устройства ввода, транспорт. Меняется только синхронизация.

0. **Поднять штатный матч локально.** В двух изолированных экземплярах подставить фабрике аргумент 1, пройти меню Online, посмотреть, создаётся ли лобби и стартует ли матч с двумя игроками. Сервис Steam при этом не создаётся. Это первое вмешательство в код игры и первый вход в пункт Online — **только по слову пользователя**.
1. **Свободный ход.** Убрать ворота кадра и реакцию на расхождение контрольных сумм состояния: каждый экземпляр считает сам, свой ввод применяется сразу. Лобби перестаёт раскалываться.
2. **Чужие игроки — по состоянию владельца.** Обновление чужого игрока удерживается, тело ставится из присланного владельцем (положение, скорость, направление, события: выстрел, бомба, предмет). Это уже умеет наш модуль мира (`playerUpdatesHeld`, секция игроков WLD1).
3. **Мир — по хосту.** Враги, зачистка комнаты, двери, переходы: снимки хоста поверх локального расчёта. Умеет модуль мира для обычных комнат, слёз и врагов.
4. **События, требующие согласия:** подбор предметов, смена этажа, смерть и возрождение — по решению хоста или владельца, по одному.

Канал на первых шагах — наш Python-транспорт через общую память; затем собственный тип сообщения в соединении самой игры.

**Что из сделанного остаётся в деле:** перехваты обновления игрока, слёз, врагов и ввода; WLD1; модель плохой сети; карта памяти; отпечаток уровня и формат сохранений; стенд с изолированными экземплярами. **Что становится запасным путём:** INP1 с воспроизведением по шагам, предсказание и сверка своего игрока, Python-лобби — они нужны, только если локальный сервис не заработает.

## Риски

- Править придётся код игры, а не только таблицы методов; бета обновляется часто, адреса надо будет искать по сигнатурам.
- **Изменённый сетевой код никогда не должен встречаться с обычными игроками**: только локальный сервис, а позже закрытые лобби с другим ключом протокола. До этого в Quick и Public Match с модулями не заходить вовсе.
- Локальный сервис — невыпущенный код, может быть неполным.
- Доверие владельцу означает, что нечестный клиент может всё; для игры с друзьями это приемлемо.
- Моды: расчёт своего персонажа у владельца переносит их без труда; моды, создающие сущности мира, видны остальным только в том объёме, который передаёт хост.
