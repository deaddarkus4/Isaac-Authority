## Текущее состояние — 20 сентября

**Этап «настоящий переход комнат» (0.5.0-experimental) пройден в живой игре 19 сентября, 21:32–21:34 UTC, по обоим маршрутам.** Подробности и таблицы: [переход комнат](docs/j460-room-transition.md).

- `door`: HOST проходит в дверь 84 → 97, реплику в ту же комнату проносит **собственная дверь игры-реплики** (игрок удерживается в проёме в позиции хоста; подавление обновления игрока двери не отключает). Модуль принимает это как новое место и продолжает: 188 снимков до двери, 226 после, слёзы по обе стороны.
- `request`: 11 снимков у двери задержаны, реплика остаётся вне проёма и сама вызывает `Game::StartRoomTransition` — **первый вызов этой функции в живой игре**, ABI подтвердился; комната достигнута за 328 мс. 189 снимков до двери, 204 после.
- В обоих: все состояния совпали с кадрами хоста побитово как float32, создано 4 / удалено 4 копии слёз, ошибок и отклонённых пакетов 0, слоты восстановлены. Summary и SHA256 — в `IsaacAuthority/Room/installation.json` (`liveTestVerified=true`).

До этого три прогона не прошли (пауза HOST, игрок не по оси двери, остановка модуля при собственном переходе реплики); каждый дал исправление. Проверен один переход через одну дверь; обратный путь, несколько переходов, большие комнаты, телепорты не проверялись. Ветки `settled` и `vanished` в живых прогонах не сработали.

**Этап врагов, первая часть, пройден в живой игре 19 сентября, 22:01–22:02 UTC** ([отчёт](docs/j460-enemy-correction-test.md), основание — [наблюдение](docs/j460-enemies-research.md)). Содержимое комнаты детерминировано её spawnSeed, поэтому реплика не создаёт копий врагов: она находит у себя тех же врагов по (тип, вариант, подтип, InitSeed) и после каждого их собственного обновления записывает состояние хоста — позицию, скорость, цель, здоровье, `State`, видимость, классы столкновений. Оба маршрута прошли с первой попытки: 5 из 5 врагов сопоставлены во всех кадрах, все записанные состояния побитово равны хосту, в конце прогона внешнее чтение обеих игр даёт расстояние 0,0 и равные `State` (без коррекции те же враги расходились за 1,5 с). Локальный ИИ за один шаг уходит от хоста в среднем на 2–3,5 единицы и в 2–5 % обновлений выбирает другое состояние. Игрок реплики на время удержания защищён от урона собственной симуляции. **Урон и смерть по решению хоста тоже пройдены (22:08 UTC, `--fight`):** HOST сам убил червя тремя слезами, здоровье 10 → 6,5 → 3 пришло на реплику в тех же снимках, враг убит штатным `Entity::Kill()` в том же снимке, где хост перестал его перечислять; в конце игры согласны, кто жив. **Не сделано:** враги и снаряды, появившиеся после загрузки комнаты, смерть врага при позднем подключении, остальные поля NPC; проверен один вид врага в одной комнате на loopback с 60 снимками в секунду — для реальной сети одной коррекции может не хватить.

**Ввод клиента на хосте — архитектурный вопрос решён положительно (22:16 UTC, [отчёт](docs/j460-client-input-test.md)).** У чтения ввода одна узкая точка: метод `WithDevice` менеджера ввода (слот 29 его виртуальной таблицы), куда приходит номер контроллера. `IsaacAuthorityInput.dll` меняет этот слот и для одного контроллера отвечает командами, принятыми по UDP (протокол INP1: оси −1…1 и кнопки, позиций клиент не шлёт). Живой тест прошёл с первой попытки без единой нажатой клавиши: игрок хоста разогнался на +175 за 0,8 с, проехал 36,6 по инерции игры, ходил влево/вверх/вниз, стрелял по команде и остановился, когда клиент замолчал на последней команде «вправо». Штатный онлайн сам представляет удалённых игроков устройствами ввода. **Не сделано:** второй игрок на хосте со своим номером контроллера (команды `addplayer` в ванили нет — нужно найти штатное присоединение кооп-игрока), чтение ввода на стороне клиента, сведение с репликой мира (снимок с двумя игроками, предсказание своего игрока на клиенте).

**Второй игрок на хосте — исследуется путь онлайна ([заметки](docs/j460-online-path-research.md)).** В игру встроен локальный сетевой сервис (`ServiceLocalhost`, `LobbyLocalhost`, `ConnectionLocalhost`) и класс `NetInputDevice` — удалённый игрок у самой игры является устройством ввода. Ключ `--networktest` (проверено на третьем изолированном экземпляре, он закрыт) сразу начинает забег в режиме онлайна: сохранение только для чтения, игроку назначается цвет; `--localhost_match` лишь переводит журнал в `localhost/log_<время>.txt`. Журнал называет штатную `Entity_Player::SetControllerId()`. Есть ключи `--set-stage=`, `--set-stage-type=`, `--load-room=` для запуска сразу в нужной комнате. **Следующий шаг:** два экземпляра с `--networktest --localhost_match` и наблюдение чтением, создаёт ли игра второго игрока и `NetInputDevice`; найти `SetControllerId` и создание игрока по строкам журнала.

**Один seed не даёт одинаковых уровней при разных сохранениях:** у HOST и REPLICA с `CZH4 8E6W` различаются 5 комнат из 15 (83, 85, 109, 126, 138). Нижняя дверь стартовой комнаты (97) общая, правая — нет. Тест требует совпадения маршрута, а не уровня; реплика нативно сверяет каждую комнату назначения. Для полного совпадения клиенту нужно сохранение хоста.

**Состояние игр.** Обе игры (HOST PID 42680, REPLICA PID 12800) стоят в стартовой комнате забега с **введённым** seed `CZH4 8E6W` — такой забег сохраняет seed при перезапуске, поэтому дальнейшие прогоны не требуют ручных действий:

```powershell
python scripts/Test-IsaacRoom.py --source-pid <HOST_PID> --replica-pid <REPLICA_PID> --restart-runs --check
python scripts/Test-IsaacRoom.py --source-pid <HOST_PID> --replica-pid <REPLICA_PID> --restart-runs --route door --binary-directory '<папка игры>\IsaacAuthority\Room'
python scripts/Test-IsaacRoom.py --source-pid <HOST_PID> --replica-pid <REPLICA_PID> --restart-runs --route request --binary-directory '<папка игры>\IsaacAuthority\Room'
```

Тест около 12 секунд управляет окном HOST (стрельба, выравнивание по двери, проход, стрельба за дверью); `--restart-runs` перед этим перезапускает оба забега (R, на экране смерти — Space). **Состояние окон — главный источник сбоев теста:** HOST при потере фокуса открывает меню паузы и держит его; REPLICA не останавливается никогда и в комнате с врагами погибает; на экране смерти Esc выводит в главное меню (так промежуточная версия теста однажды вывела REPLICA в меню — забег восстановлен через меню, тест теперь шлёт Esc только при живом игроке). Тёмный экран HOST — проклятие темноты, а не пауза; паузу определять по счётчику кадров `Game+0x264f8`. После каждого прогона игры остаются в комнате с врагами — возвращать их `--restart-runs --check`.

## Цель и принятое направление

Пользователь выбрал **замену сетевой модели Isaac на авторитетный хост**: хост считает мир, клиенты предсказывают движение и корректируются по его состоянию. Временное расхождение не должно разделять лобби, задержка клиента не должна останавливать хост. Исправление отдельных случаев старого lockstep не является основным направлением; сохранённые десинки нужны как проверочные случаи.

**Полноценного альтернативного мультиплеера в игре пока нет.** Между двумя настоящими J460 проверены реплика игрока, жизненный цикл обычных слёз (создание, состояние, удаление) и настоящий переход через дверь в ту же комнату. Добавлены ID сущностей и защита от пакетов старой комнаты. Враги, предметы и боевая логика пока не синхронизированы.

## С какого шага продолжать

Пользователь подтвердил готовность; наблюдение и `-CorrectOnce` **успешно выполнены**. Журналы скопированы в `Binaries/diagnostics/player-step/`: `player-step-40064-11572156.jsonl` и `player-step-40064-11580375.jsonl`.

Реализован, установлен и **проверен в живом J460** [сетевой эксперимент](docs/j460-network-state-test.md). Готовность пользователя получена; пять абсолютных состояний с малыми сдвигами и возвратом в исходную точку успешно применены. Summary: `Binaries/diagnostics/network-state/network-21580-20260919-192621-354447.summary.json`. Активный перехват после проверки отключён.

Настоящий источник и реплика одного игрока также **реализованы и проверены**. Итог: `Binaries/diagnostics/game-pair/pair-20260919-195656-152409.summary.json`. Передано 541 состояние, применено 271; 270 промежуточных снимков заменены более свежими в очереди. Во время паузы передачи реплика не рассчитывала движение самостоятельно, хост продолжал обновления.

Реализован и проверен жизненный цикл обычных слёз: ID учитывает адрес/seed/локальный индекс, полные снимки создают и удаляют копии, клиент не считает их движение/столкновения самостоятельно. Итог: `Binaries/diagnostics/world/world-20260919-203818-378209.summary.json`. Контрольная смена epoch проверила очистку живой копии и отсечение старых пакетов, **но не реальную загрузку следующей комнаты**.

Настоящий переход обеих игр [реализован](docs/j460-room-transition.md): реплика находит комнату хоста в собственном уровне, сверяет её и запрашивает штатный переход игры. Живой тест `scripts/Test-IsaacRoom.py` прошёл по маршрутам `door` и `request`. Согласование seed пока ручное: нативный путь через консоль (`Console::RunCommand`, RVA `0x28cdc0`) найден, но безопасная точка вызова перезапуска не установлена.

Дальше — расширение репликации на врагов, другие снаряды, предметы/урон/награды. Враги — первый кандидат: сразу за дверью у каждой игры свои враги, реплика получает собственный урон и погибает независимо от хоста, а подавить можно только обновление сущностей, но не логику комнаты (дверь сработала при подавленном обновлении игрока). Также остаются передача ввода клиента хосту, игровое предсказание и автоматическое согласование seed/сохранений. Не повторять завершённые проверки без новых изменений или конкретной причины.

[Описание и ограничения игрового теста](docs/j460-player-step-test.md). Адаптер проверяет одного локального игрока и пустой список сетевых устройств; подготовленный тест не запускать поверх текущего онлайн-забега.

## Не сделано и ограничения

- ABI/перехват и разовая запись X проверены в одном одиночном забеге J460. Смена комнаты, уничтожение игрока и длительная работа с коррекциями не проверены. Полная декомпиляция большой функции обновления игрока не завершилась за выделенный лимит.
- Две игры проверены только в пустых стартовых комнатах: loopback, один выбранный игрок, сессия до 30 секунд, пакет до 250 мс. Ограничение скачка 128 пикселей относится к модулю Pair; World имеет отдельные диапазоны WLD1 и проверку контекста комнаты. Полноценные коллизии, бои, переходы и большие коррекции не проверены.
- Реплика подавляет обновление выбранного игрока и созданных ею обычных слёз; остальные сущности мира продолжают собственную симуляцию. У копий слёз отключены столкновения и урон. Нет интерполяции и автоматического согласования seed/сохранений; смена комнаты проверена для одного перехода через одну дверь и покрывает только обычные комнаты сетки в измерении 0.
- Сетевые ID пока реализованы только для набора до 16 стандартных слёз `2.0.0` в одной комнате. Нет синхронизации врагов, других снарядов, урона, предметов, сохранений, переподключения и миграции хоста; нет интернет-транспорта/аутентификации.
- Старый внешний state reader даёт best-effort чтение. Source-модули публикуют данные игрока и поддерживаемых слёз после обновления игрока через счётчик поколений; **границы полного шага и атомарного снимка мира по-прежнему нет**.
- Старые issues, EID-миграция и прочие замечания исследованы в [issue-triage.md](docs/issue-triage.md); не считать все перечисленные проблемы исправленными.
