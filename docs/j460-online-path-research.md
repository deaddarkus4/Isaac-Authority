# Путь онлайна: откуда взять второго игрока на хосте

**19–20 сентября 2026. Исследование, этап не завершён.** После того как [ввод клиента на хосте](j460-client-input-test.md) заработал для единственного игрока, остался вопрос: как получить на хосте второго игрока со своим номером контроллера. Кооператив в этой игре запускается через отдельный пункт меню Online, поэтому разбирался путь онлайна. Ничего в HOST и REPLICA на этом этапе не менялось; эксперименты шли на третьем, изолированном экземпляре, который затем закрыт.

## Что есть в игре

Строки и RTTI бинарника J460:

- **Локальный сетевой сервис.** Рядом со `ServiceSteam` и `LobbyEOS` есть `KAGE::Network::Multiplayer::ServiceLocalhost`, `LobbyLocalhost`, `ConnectionLocalhost` и сообщения `Invalid localhost welcome message`, `Failed to send localhost data`, `Localhost lobby values currently not supported`. То есть в игру встроен транспорт онлайна между процессами одной машины, без Steam-лобби.
- **`NetInputDevice`.** Удалённый игрок — устройство ввода: `PlayerManager::GetPlayerSlotFromController() could not find NetInputDevice with controllerID(%d)`. Это согласуется с разбором чтения ввода: при номере контроллера −1 игра опрашивает список сетевых устройств `Manager+0x4b3d8`.
- **Ключи командной строки:** `--networktest`, `--localhost_match`, `--set-stage=`, `--set-stage-type=`, `--load-room=`, `--luadebug`, `--luaheapsize=`. Команды консоли `addplayer` в ванили нет.

## Что делают ключи (проверено запуском)

| Ключ | Поведение |
| --- | --- |
| `--localhost_match` | В `main` только переключает журнал на `localhost/log_<время>.txt` в папке сохранений, чтобы экземпляры не писали в один файл. Папку `localhost` игра не создаёт — без неё журнала нет вовсе. |
| `--networktest` | Булев флаг: `0xc71673` → `Manager+0x4b3d4` (байт перед списком сетевых устройств). **Меню остаётся обычным**: титул, выбор файла, главное меню, в пункте Online — Quick Match, Public Match, Friend Match, Daily Run, Options. Что флаг меняет внутри онлайна, не установлено: в журнале нет строки о выбранном сетевом сервисе, а входить в матч под аккаунтом Steam пользователя вслепую нельзя. |
| `--set-stage=N`, `--set-stage-type=N`, `--load-room=…` | Запуск сразу на заданном этаже и в заданной комнате (`Manager+0x4b19c…`). Не проверялись; полезны для тестов без прохода в дверь. |

**Исправление.** Первая версия этого документа утверждала, что `--networktest` пропускает меню и сразу начинает забег в режиме онлайна. Это было неверно: забег запустили мои собственные нажатия Enter, отправленные вслепую «чтобы пропустить ролик», без снимка экрана между ними. Пользователь заметил меню; повторный запуск со снимком после каждого нажатия показал обычную последовательность экранов. Строки `Setting PersistentGameData ReadOnly to True` и назначение цвета игроку относятся к тому случайно начатому забегу и ничего не говорят о флаге.

Побочное наблюдение того же журнала: изолированный экземпляр загрузил содержимое десяти модов мастерской (`LOADED MOD …/mods/<мод>/content/`) из своей рабочей папки, хотя в его `options.ini` стоит `EnableMods=0`, а папка создавалась пустой. Steam раскладывает подписки в папку `mods` рабочего каталога. Это может влиять на генерацию комнат и должно быть проверено как возможная причина расхождения уровней HOST и REPLICA — раньше оно приписывалось только разным сохранениям.

Журнал обычного забега называет штатный способ привязки игрока к контроллеру: `Entity_Player::SetControllerId() Setting controller ID to 0, (Prev: -1)`, затем `Assinging player entity 0 (ControlerIndex = 0) to HUD slot 0`.

## Инструменты

- `IsaacAuthorityLaunch … -- АРГУМЕНТЫ` и `Start-IsaacReplica.ps1 -GameArguments` передают ключи игре; для `--localhost_match` создаётся папка журнала.
- `ExportIsaacRoom.java`: `data:RVA` — все функции, ссылающиеся на глобальную переменную; `addr:RVA` — функция, содержащая адрес.

## Следующий шаг

Сначала статически выяснить, кто читает `Manager+0x4b3d4` и когда выбирается `ServiceLocalhost` вместо `ServiceSteam`: пока это неизвестно, любой пункт меню Online может создать настоящее лобби под аккаунтом пользователя. Только после этого — два изолированных экземпляра и наблюдение чтением, появляется ли второй игрок и `NetInputDevice` в `Manager+0x4b3d8`. Параллельно — найти по строке журнала `Entity_Player::SetControllerId` и функцию создания игрока, чтобы добавить второго игрока в обычном забеге и отдать его контроллер модулю ввода.

Важно помнить цель: штатный онлайн — это lockstep, который проект заменяет. От него нужен способ создать второго игрока и устройство ввода для него, а не его барьер шага и проверка рассинхронизации.
