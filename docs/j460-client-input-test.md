# Ввод клиента на хосте

**19 сентября 2026, 22:16 UTC: живой тест прошёл с первой попытки.** Команды, пришедшие по UDP, управляют настоящим игроком J460 через штатный код движения и стрельбы игры. Тест не нажал ни одной игровой клавиши. Это проверка главного архитектурного вопроса второй половины модели: может ли хост симулировать игрока по сетевому вводу, а не по позициям.

Принято 390 команд, отклонено 0. Перехват подставил 3352 чтения значений, 2723 «нажато» и 1676 «только что нажато»; 11410 чужих запросов (другие контроллеры, меню, действия вне набора) прошли к оригиналу. Слёз без команды не было. Слот менеджера ввода восстановлен, ошибок сети нет. Summary: `Binaries/diagnostics/input/input-20260919-221651-006061.summary.json`, рядом — ряд наблюдений позиции.

Разгон и выбег в нейтральных фазах показывают, что работает именно физика игры: клиент передаёт только наклон осей, а ускорение, трение, скорость персонажа и темп стрельбы считает хост. Команда с осью больше 1 отвергается форматом — клиент не может попросить скорость выше полной.

## Как игра читает ввод (J460)

Привязки Lua (`Input.GetActionValue`, `IsActionPressed`, `IsActionTriggered`, `EntityPlayer.ControllerIndex`, `GetMovementInput`) дали всю цепочку; экспорт — `Binaries/research/j460-input*/`, профиль — `native/IsaacNetProbe/profiles/j460-input.json`.

| Назначение | Адрес или смещение |
| --- | --- |
| Номер контроллера игрока | `Entity_Player+0x1618`; у единственного игрока 0 (клавиатура) |
| `Entity_Player::GetMovementInput` / `GetShootingInput` | RVA `0x379360` / `0x379620` |
| Значение действия для игрока `(action, controller, entity)` / «нажато» | RVA `0x5562d0` / `0x556110` |
| Менеджер ввода / его виртуальная таблица | объект RVA `0x857b18` / таблица RVA `0x782950` |
| `WithDevice(controller, reader, in, out, deviceId)` | слот 29, RVA `0x620fb0`, thiscall, `ret 0x14` |
| Читатели: значение / «нажато» / «только что нажато» | RVA `0x620ab0` / `0x620940` / `0x6209e0` |

`0x5562d0` сначала даёт слово колбэкам модов (`MC_INPUT_ACTION`), затем, если контроллер равен −1 и есть сетевые устройства (`Manager+0x4b3d8`), опрашивает их виртуальный метод `+0x38`, иначе вызывает `WithDevice` менеджера ввода с номером контроллера и функцией-читателем. Читатель значения пишет float в `out` и возвращает «не ноль»; остальные возвращают bool. **Штатный онлайн тоже представляет удалённых игроков устройствами ввода** — это согласуется с выбранным направлением: хост симулирует, клиент шлёт ввод.

## Реализация

`IsaacAuthorityInput.dll` (`src/input_adapter.cpp`, чистая логика — `input_state.cpp`) меняет один слот виртуальной таблицы менеджера ввода — тем же приёмом, что слоты Update сущностей; код игры не патчится. Перехват отвечает сам, только если запрос идёт к управляемому контроллеру, читатель — один из трёх известных, действие — из набора (4 движения, 4 направления стрельбы, бомба, предмет, карта, сброс) **и есть свежая команда** (не старше 250 мс). Иначе решает настоящее устройство: молчащий клиент — нейтральный клиент, а не залипшая клавиша. «Только что нажато» сообщается один раз на команду, впервые удерживающую действие.

Протокол INP1: 56 байт, little-endian — сессия, возрастающий номер, время, контроллер 0–7, четыре оси −1…1, маска кнопок. Проверяются размер, версия, резерв, конечность и диапазон осей, контроллер, сессия, порядок и свежесть. Только loopback, сессия до 30 секунд.

## Что это даёт и что остаётся

Ответ на архитектурный вопрос положительный: у ввода одна узкая точка, подстановка идёт по номеру контроллера, и игра симулирует такого игрока сама. Стены нет.

- **Второй игрок на хосте.** Сейчас управляется единственный игрок с контроллером 0. Нужен игрок клиента с собственным номером контроллера; в ванильной консоли команды `addplayer` нет (строка в бинарнике не найдена). Нужно найти штатное присоединение кооп-игрока и вызвать его без физического контроллера.
- **Сторона клиента.** Тот же перехват в режиме чтения: брать ответ настоящего устройства для контроллера 0 на клиенте и отправлять хосту. Не сделано.
- **Сведение с репликой мира.** Адаптеры мира требуют ровно одного игрока и передают одного; с двумя игроками снимок должен нести обоих, а клиент — предсказывать своего (как в стенде `IsaacAuthorityLab`).
- Не проверены кнопки (бомба, предмет), аналоговые значения между 0 и 1 и «только что нажато» по смыслу — в тесте только оси ±1.
