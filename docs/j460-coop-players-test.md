# Два игрока в снимке мира

**19 сентября 2026, 23:04 UTC: живой тест прошёл.** Это первый шаг сведения двух половин модели: хост публикует **всех** игроков забега с номером контроллера, реплика показывает обоих. Первого игрока хоста вела клавиатура HOST, второго — команды клиента INP1 по UDP; тест не нажал для второго игрока ни одной клавиши. Реплика получила своего второго игрока тем же штатным присоединением локального кооператива.

Зеркальные смещения — не совпадение теста, а свойство модели: оба игрока хоста считаются одной и той же физикой игры, клиент передаёт только наклон осей. Summary: `coop-20260919-230429-841746` в `Binaries/diagnostics/coop/`, рядом — журналы обоих модулей мира и трёх сессий модуля ввода (присоединение на реплике, присоединение на хосте, ведение второго игрока).

## Что пришлось исправить по дороге

- **Попытка 1 (23:01 UTC): REPLICA присоединила второго игрока, HOST отказал в загрузке модуля ввода.** Причина — установщик: пакет `Coop` положил модуль ввода под тем же именем (`IsaacAuthorityInput-<хеш>.dll`), под каким он уже был загружен в HOST из пакета `Input`. Инжектор различает модули по имени файла и отказывает, если одноимённый модуль загружен из другой папки. Это правильное поведение инжектора; теперь копия модуля в пакете носит имя пакета (`IsaacAuthorityCoopInput-<хеш>.dll`).
- **Попытка 2 (23:02 UTC): все сверки прошли, не прошло ожидание сценария.** После рестарта забега игроки стоят у нижней стены первой комнаты (y = 380 и 389,7), и второй игрок, посланный вниз, упёрся в стену на y = 410, пройдя 20 единиц. Модули работали верно; вертикальный шаг сценария теперь идёт вверх.
- **Попытка 3: тест отказался стартовать.** Windows не отдала фокус окну игры, защита `require_focus` сработала до первого нажатия. Ни одна клавиша не была послана, модули не подключались.

## Формат: WLD1 версии 3

Заголовок прежний (96 байт) и по-прежнему несёт тело первого игрока. Прежде зарезервированное поле `+92` в версии 3 — число игроков (1–4). Секция игроков идёт последней, после секции врагов: по 24 байта на игрока — номер контроллера (0–7), позиция и скорость (4 float32), резерв = 0. Первая запись секции повторяет тело из заголовка; декодер отвергает пакет, если они расходятся побитово.

У каждого кадра одно написание: версия 1 — без секций, 2 — только враги, 3 — есть секция игроков (с врагами или без). Один игрок на контроллере 0 пишется только версиями 1/2 — байт в байт как раньше, поэтому замороженные пакеты `World`, `Room` и `Npc` и их журналы остаются совместимы. Версия 3 с одним игроком на контроллере 0 отвергается. Два игрока могут делить контроллер (Jacob и Esau), поэтому идентичность игрока — **место в списке**, а номер контроллера говорит, чей ввод ведёт игрока на хосте; по нему клиент найдёт своего.

Слот публикации вырос с 3072 до 3168 байт. `isaac_world.read_slot` читает столько, сколько указано в дескрипторе модуля (`bytes`), и принимает оба размера: скрипты репозитория снова совместимы с установленными бинарниками пакета `Npc`.

## Реализация

`world_adapter.cpp` с флагом `ISAAC_WORLD_PLAYERS` (цели `IsaacAuthorityCoopSource` / `IsaacAuthorityCoopReplica`, вместе с `ROOMS` и `NPCS`). Без флага адаптер по-прежнему требует ровно одного игрока и не читает контроллер — поведение прежних модулей не изменилось.

- `Local()` читает весь список игроков (`Game+0x1baa8`, до четырёх); состав (`Team`) — часть контекста: на хосте смена состава начинает новое поколение (epoch), на реплике — останавливает модуль.
- Перехват обновления игрока вызывается для каждого игрока. Шаг игры несёт одно «ведущее» обновление: **источник снимает мир после обновления последнего игрока списка** (все тела уже после шага), **реплика применяет снимок с обновлением первого**; остальные игроки реплики только удерживаются в теле последнего снимка. Счётчик `updateOrderSurprises` проверяет допущение, что игра обновляет игроков в порядке списка: в живом прогоне 0 на обеих сторонах.
- Реплика применяет снимок, только если число игроков в нём равно её собственному (`rosterMismatches`); защита от ударов врагов (`Shield`) и удержание распространяются на всех игроков.
- Номер контроллера — `Entity_Player+0x1618`; значение вне 0–7 не проходит проверку формата, снимок не публикуется.

Новый тест `scripts/Test-IsaacCoop.py`: рестарт забегов, присоединение второго игрока в обеих играх через модуль ввода (REPLICA первой, HOST последним — он держит фокус), затем 7,5 секунды сценария и сверка. Установка — `scripts/Install-IsaacRoom.ps1 -Stage Coop` (пакет 0.8.0-experimental, `IsaacAuthority/Coop`: два модуля мира, копия модуля ввода, скрипты).

```powershell
.\scripts\Build-IsaacAuthority.ps1
python -m unittest discover -s scripts/tests -p test_*.py
.\scripts\Install-IsaacRoom.ps1 -Stage Coop
python '<папка игры>\IsaacAuthority\Coop\Test-IsaacCoop.py' --source-pid <HOST_PID> --replica-pid <REPLICA_PID> --restart-runs
python scripts/Test-IsaacRoom.py --source-pid <HOST_PID> --replica-pid <REPLICA_PID> --restart-runs --check
```

**11/11 CTest и 26/26 Python-тестов проходят.** Новое: секция игроков на двух языках (круговой проход, усечение, резерв, расхождение заголовка и первой записи, контроллер вне диапазона, единственность написания, общий контроллер, переполнение состава), чтение слота старого размера, контракты двух новых модулей.

## Ограничения

- Одна стартовая комната без врагов и без двери; переход комнат и бой с двумя игроками не проверялись. Loopback, сессия до 30 секунд.
- Второй игрок реплики создаётся тем же присоединением, то есть на машине клиента тоже нужно второе устройство ввода (здесь — DualSense по Bluetooth; он не XInput). Кандидат на замену — `PlayerManager::SpawnCoPlayer2`, см. [заметки о REPENTOGON](repentogon-reference.md).
- Состав фиксирован на время сессии реплики: присоединение игрока посреди сессии реплика не переживает (останавливается чисто).
- Персонаж второго игрока — тот, что предложен по умолчанию; совпадение персонажей в двух играх не сверяется. Здоровье, предметы и смерть игроков не синхронизированы.
- На этом этапе команды второго игрока слал тест. Собственный ввод клиента добавлен следующим этапом — [замкнутая петля](j460-closed-loop-test.md); предсказания своего игрока на клиенте ещё нет.
