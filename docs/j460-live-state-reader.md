# Чтение состояния J460 и передача в сетевой прототип

18 сентября 2026 выполнено чтение **живого процесса Isaac**, PID 63880, без приостановки, внедрения кода или записи в его память. В забеге были два игрока: порченый Айзек и Lazarus. Путь к игре взят у процесса, база модуля определена с учётом ASLR. SHA256 EXE и префикс загруженной функции получения игрока проверены.

## Реализованный путь

`isaac-ng.exe → ReadProcessMemory → история кадров → UDP 127.0.0.1 → IsaacAuthorityLab observer`

Это реальное состояние игры, а не синтетическое движение из первоначального стенда. Наблюдатель — отдельный C++-процесс, не второй игровой клиент. В память игры ничего не записывается. Снимок содержит только позиции/скорости двух игроков; состояние врагов, предметов и остальных систем в сетевой протокол пока не переносится.

Первое чтение: 147 принятых снимков за пять секунд, один отброшен из-за изменения данных во время чтения. Проверка передачи: 145 принятых снимков, два отброшены; 136 различных кадров передано и принято по UDP, ошибок декодирования нет. Последний кадр 28782: обе позиции и скорости совпали с исходными float32 побитово.

Артефакты:

- `Binaries/diagnostics/state-reader/state-20260918-182533-70fa3c80.jsonl`
- `Binaries/diagnostics/state-reader/bridge-20260918-182854-db40b789.jsonl`

## Откуда взяты поля

Смещения перечислены в [профиле](../native/IsaacNetProbe/profiles/j460-state-reader.json). `Game::GetPlayer` / `GetNumPlayers`, RVA `0x17870` / `0x178d0`, дают границы массива указателей `+0x1baa8/+0x1baac`. Вызывающий код J460 использует глобальный указатель RVA `0x871678`; это другой объект, чем менеджер RVA `0x87169c`.

Позиция `+0x33c/+0x340` подтверждается вычислением расстояния до игрока в J460 (экспорт `004b8190.c`). Кандидат скорости `+0x360/+0x364` проверен на живых данных независимо от REPENTOGON. В сравнении 278 из 290 пар положения/скорости живых объектов **побитово совпали** с pre/post полями истории в окне от наблюдаемого сетевого кадра −1 до +2. Это проверка назначения полей, не гарантия точного момента каждого внешнего чтения.

Функция `0x4fe3a0` печатает framestate: из указателя комнаты `Game+0x18300` берёт кольцевой буфер на 32 записи по 24 байта (`+0x1310`, начало/количество `+0x1610/+0x1614`). Каждая запись содержит номер кадра, begin/end/capacity сущностей и контрольные суммы. Запись сущности занимает 56 байт: index/type/variant/subtype/checksum/RNG, затем pre-position/pre-velocity/post-position/post-velocity. Функция сравнения `0x4ffc70` независимо подтверждает назначение post-velocity.

Декомпиляция: `Binaries/research/j460-authority-state-v2/`. Скрипт `reverse/ghidra/ExportIsaacAuthority.java` расширен этими точками. Сырые файлы декомпиляции остаются локальными артефактами, а не частью распространяемого приложения.

## Защита от некорректного чтения

Процесс открывается только с `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ`. Проверяются пределы указателей/массивов, конечность чисел, тип игроков. Новейшая запись истории пропускается; заголовки, полезная нагрузка истории, указатели и выбранные поля игроков читаются повторно. Изменившийся снимок отбрасывается. JSON явно содержит `atomic:false`.

Внешнее чтение всё равно не даёт атомарности: возможны изменения внутри кадра, освобождение/повторное использование адреса и переходы комнат. Игровой поток не остановлен. Поэтому эти данные подходят для наблюдения и исследования, но ещё не для авторитетной коррекции живой игры.

## Запуск

Для обычного чтения на этом ПК (нужны Python и запущенная оригинальная J460):

```powershell
.\scripts\Read-IsaacState.ps1 -Seconds 10
```

При нескольких процессах требуется `-ProcessId`. Путь игры вручную не нужен. Существующий файл снимка не перезаписывается.

Проверка всей цепочки с двумя игроками и доступной историей кадров:

```powershell
.\scripts\Build-IsaacAuthority.ps1
$isaacProcess = Get-Process isaac-ng
python scripts/Test-IsaacStateBridge.py --pid $isaacProcess.Id
```

Восемь тестов парсера/гонок/формата:

```powershell
python scripts/tests/test_isaac_state.py
```

## Граница текущего этапа

Режим observer не предсказывает ввод и не меняет игру, не обходит официальный сетевой барьер. Индекс сущности здесь используется только для сортировки пары игроков, не как готовый постоянный сетевой ID. Epoch моста меняется при откате счётчика кадров; это не полноценный протокол смены комнаты. При отсутствии пары игроков или истории передача пропускается.

Следующий шаг — перехват границы игрового шага и проверка безопасного применения состояния в отдельном локальном тесте. Писать координаты поверх текущего онлайн-забега означало бы вмешаться в старую симуляцию, а не заменить её сетевую модель.
