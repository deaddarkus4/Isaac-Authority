# Проклятие лабиринта и подбор наград: два броска, которые каждая игра делала за себя (0.1.8, 0.1.9)

**22 сентября 2026, вечер.** Два расхождения, замеченные на стенде вчетвером; про первое пользователь сказал, что его же
видели игроки в матчах через Steam. Оба — один класс: **игра решает броском, а бросает каждая сторона своим генератором.**
Тот же класс, что сделка в 0.1.5 и предмет с пьедестала в 0.1.7.

## 1. «Вышел из комнаты и оказался через комнату»

### Что видели

Хост вышел из curse room и оказался не в Start Room, а на комнату дальше; остальных утащило следом. По журналам:

```
A (хост):  Room 10.19 (curse)  ->  Starting room transition (type 0)  ->  Found a candidate  ->  Room 1.748
B (гость): Room 10.19 (curse)  ->  Starting room transition (type 0)  ->  Room 1.2 (Start Room)
                               ->  Starting room transition (type 1)  ->  Room 1.748      <- наш запрос, следование
```

Раскладка этажа (шестой столбец сверху вниз): **97 — curse room**, **84 — Start Room**, **71 — trap room**. У хоста
`visits` Start Room остался **1**, у обоих гостей — **2**: хост в неё действительно не заходил.

Наш модуль тут ни при чём: перехода он запрашивает ровно в одном месте (`FollowRoom`), и там счётчик растёт всегда, а у
хоста `rooms followed 0 (failed 0)`.

### Причина

`Level::ChangeRoom`, RVA `0x33fc80`. Под веткой проклятия лабиринта:

```c
if ((~f2 & (f1 | global | game[3]) & 0x20) != 0 && ...) {   // 0x20 = CURSE_OF_MAZE
    if (FUN_006eef60() % 10 == 0) {                          // бросок: 1 из 10
        ...                                                   // перебрать комнаты через GetRoomByIdx (0x340bc0),
        ...                                                   // пропустить типы 7, 8 и 10 (тайная, сверхтайная, curse),
        param_1[0x60c1] = кандидат;                           // и записать найденную прямо в Game+0x18304
        IsaacLog("Found a candidate\n");
    }
    ...
    if (FUN_006eef60() % 5 == 0) { ... }                      // второй бросок: перемешать этаж
}
```

Проклятие у всех одно (общее сохранение и seed — прочитано в трёх живых играх: `curses 0x20`, `['Maze']`), а **броски у
каждого свои**. Кого-то швырнуло, кого-то нет; комнаты разъехались, и дальше модуль честно собрал всех за тем, кто
«сменил комнату позже». Со стороны это и выглядит как «нас всех куда-то утащило».

### Сделано: правило `maze` (бит `0x800000`, версия 0.1.8, протокол 9)

Бросает только хост. У гостя обе ветки перепрыгиваются — тем самым переходом, который игра делает сама, когда бросок не
выпал, так что ничего не выдумано: удержан бросок, а не его ответ.

| | RVA | было | стало |
| --- | --- | --- | --- |
| Бросок «1 из 10» | `0x33ff00` | `0f 85 20 03 00 00` (jnz мимо поиска кандидата) | `e9 21 03 00 00 90` |
| Бросок «1 из 5» | `0x340236` | `0f 85 02 01 00 00` | `e9 03 01 00 00 90` |

Патч ставится при старте модуля только у гостя и только при совпадении байтов, снимается при остановке. В комнату, куда
швырнуло хоста, гости приходят следованием, как и в любую другую. В `.status` у гостя: `the maze's rolls are the host's here`.

Проверено чтением живой памяти: у хоста байты игры нетронуты, у обоих гостей стоит безусловный переход. **Живьём эффект не
наблюдался** — в следующем забеге проклятие не выпало. Забег, где оно было: seed `JEEC 6QKV`.

### Попутно: гонка при одновременной смене комнаты

Комната у нас — событие с логическими часами (`roomEpoch`). Когда двое входят в разные двери в один миг, их номера равны,
и гость, услышавший обоих, выбирал лидера **первым попавшимся в списке соседей**. Отсюда метание: один гость сходил
1.777 → 7.1 → 1.777. Предпочтение хоста было только при сравнении со своим номером, между кандидатами — нет.

Сделано: при равных номерах лидер — всегда хост. Живьём не проверено (случай не повторился).

## 2. Награды после босса: гость подбирал то, чего у остальных нет

### Что видели

Комната босса зачищена, игроки ожили, пользователь (он играл за гостя B) пошёл собирать выпавшее. У гостя C с пингом
150 мс на полу осталась россыпь предметов, которых у других уже не было.

| | взято своим | проиграно чужих | промахов | копий создано / убрано |
| --- | --- | --- | --- | --- |
| A (хост) | 1 | 20 | **3** | 0 / 0 |
| B (там играл человек) | 23 | 1 | 0 | 9 / 8 |
| C (гость, пинг 150) | 0 | 21 | **3** | 7 / **2** |

### Причина

Когда комната зачищается, **каждая игра роняет свои награды** — сиды у них разные. Гость приводит свой список к хостовому
за несколько снимков (`ApplyDrops`: лишнее местное удаляется через `kDropMadeHereSnapshots`, хостово создаётся), и в этом
промежутке игрок успевает подобрать **своё**. В других играх такого предмета нет вовсе: взятие некуда применить (`missed`),
а у отставшего с пингом его собственные награды остаются лежать.

### Сделано: подбор придерживается до слова хоста (версия 0.1.9, протокол 10)

У гостя касание вещи, которую хост ещё не назвал (её нет в `knownDrops`), не берётся: игра отвечает ровно то, что отвечает
касанию копии чужого игрока (цена/ожидание — её собственный ответ, не зависящий от взятия). Ждёт `kOwnTouchWait` = 30
кадров — полсекунды, с запасом на настоящий пинг. Пришло слово хоста раньше — берётся сразу; не пришло за полсекунды
(список хоста переполнен, `kMaxDrops` = 64) — берётся всё равно, чтобы вещь не стала неподбираемой навсегда.

### И разбивка промахов по причинам

`takenMissed` сливал три разных случая, и по одному числу в матче через Steam нельзя было понять, что сломалось. Теперь
рядом с ним идут три своих счётчика и четвёртый — про придержку:

- `takenNoRecord` — запись о взятии не доехала (в теле едут последние `kMaxTaken` = 8);
- `takenElsewhere` — взято в комнате, куда эта игра не пришла, а владелец ушёл дальше;
- `takenNoTwin` — брать было нечего (наш случай);
- `ownTouchesHeld` — сколько касаний придержано до слова хоста.

В `.status` и в стенде: `takings told … / missed N (no record …, elsewhere …, nothing here to take …; own touches held …)`.

**Живьём не проверено.** Что смотреть: зачистить комнату с наградами и сразу побежать собирать — `nothing here to take`
должно остаться 0, `own touches held` больше нуля, и у гостя с пингом на полу не должно оставаться лишнего.

## Версии и совместимость

| Версия | Протокол | Что |
| --- | --- | --- |
| 0.1.8 | 9 | правило `maze`, тай-брейк комнаты в пользу хоста |
| 0.1.9 | 10 | придержка подбора у гостя, разбивка `missed` |

Маска правил стала `0xFFFFFF`; `maze` выключается как любое другое правило (`-Without maze`). Протокол поднят дважды не
из-за формата обмена — он не менялся, — а потому что участник прежней версии в обоих случаях ведёт себя иначе и растаскивает
мир: бросает за лабиринт сам или хватает то, чего у других нет. Рукопожатие такие матчи не соберёт.
