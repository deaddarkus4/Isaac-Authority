# Стенд на четверых: впуск игрока проверен вживую, и чего это стоило (0.1.8)

**22 сентября 2026, день.** Просьба пользователя: четыре окна в одном лобби, у одного игрока пинг 150 мс. Собрано; попутно
вскрылись три вещи, из-за которых стенд больше двух окон до сих пор не поднимался, и **впервые вживую проверено главное
из 0.1.7 — матч с работающими модулями не впускает вошедшего, и спуск на этаж при этом никого не вешает.**

## Как поднимается стенд на четверых

Порядок важен, и он не тот, что для пары:

1. `Start-IsaacNativePair.ps1 -Saves A,B,C -GameExecutable Binaries\game-copy-installed\isaac-ng.exe` — **три** окна, не
   четыре. Ключ обязателен: модуль, установленный в настоящую папку игры, иначе грузится в тестовые экземпляры сам, и
   проверяться будет не та сборка (ловушка из 0.1.4).
2. `Enter-IsaacNativeLobby.py host <A> intro …`, затем `guest` для B и C, затем `ready <A> lobby` — матч стартует втроём.
3. `Test-IsaacNative.py --installed --play` — модули получают `.cfg` и включаются; `localhost-<pid>.ping` для гостя с пингом.
4. **Четвёртый поднимается отдельно и только теперь**: `Start-IsaacReplica.ps1` + `IsaacAuthorityAttach.exe localhost`,
   запись о нём дописывается в `Binaries\game-instances\native-pair.json`, и `Test-IsaacNative.py` перезапускается, чтобы
   выдать `.cfg` и ему. Дальше `Enter-IsaacNativeLobby.py guest <D> intro` — он входит в лобби идущего матча и жмёт «готов».

### Почему именно так, а не проще

- **Матч не стартует, пока в лобби кто-то не готов.** Держать D в лобби с самого начала и запустить забег втроём нельзя:
  игра ждёт всех. Значит D обязан входить уже в идущий матч.
- **Игра, побывавшая в меню Online, список лобби больше не обновляет.** Экземпляр, который вышел из лобби и вернулся в
  Quick Match, получает «No lobbies were found» и предлагает создать своё — проверено трижды, в том числе с остановленными
  модулями и без пинга, так что дело не в нас. Свежий процесс находит лобби идущего матча сразу (на локальном сервисе
  данных лобби нет, поэтому диалог «войти в идущую» не показывается — вход происходит молча). Отсюда правило: **четвёртого
  поднимать заново, а не возвращать из меню.**
- **Соседями модулю называются только участники матча.** Стенд раздавал всем четверым адреса всех четверых, и три
  работающих модуля ждали привета от того, кто сидит в лобби: `neighbours answered 2 of 3`, ни один не дошёл до `LIVE`.
  Теперь `Test-IsaacNative.py` считает соседями только тех, у кого в журнале есть матч, а ждущему в лобби всё равно даёт
  адреса остальных — чтобы он заговорил с первого кадра, если его когда-нибудь впустят.

## Дефект самой игры: лобби убивает всех, кто не в меню Online

Первый же запуск четырёх окон кончился тем, что **три из четырёх закрылись одновременно**, как только первое создало лобби.
Дампы (`%LOCALAPPDATA%\CrashDumps\isaac-ng.exe.*.dmp`, три штуки) у всех одинаковы: чтение по адресу `0x2c`, RVA `0x673EC2`,
в потоке сетевого кода игры.

```
0x673E9E  mov eax,[ebp-38h]      ; лобби по id
0x673EA1  test eax,eax
0x673EA3  jne 0x673EA9           ; нашли - считаем, можно ли войти
0x673EA5  xor edx,edx            ; НЕ нашли - указатель обнуляется...
0x673EA7  jmp 0x673EC2           ; ...и прыжок прямо на его разыменование
0x673EC2  mov al,[edx+2Ch]       ; <- смерть
```

Это функция «можно ли войти в это лобби»: дальше она смотрит, есть ли место (`+0x2c` против вместимости вектора `+0x20`/`+0x24`),
открыто ли оно (`+0x34`, `+0x30`), и отвечает `bl`. Ветка «лобби не найдено» ведёт не к ответу «нельзя», а к чтению нуля.

Через Steam она недостижима: вопрос задают только про лобби, о котором игра слышала. **Localhost-сервис рассылает сведения
о лобби всем окнам игры**, поэтому каждый, кто в этот момент не в меню Online, получает вопрос про лобби, которого не знает.
Пара окон этого не ловила: к моменту создания лобби оба уже были внутри Online.

**Починено в стендовом модуле** (`localhost_adapter.cpp`): прыжок по `0x673EA7` переведён на `0x673EE9` — туда, куда игра сама
идёт для лобби, в которое войти нельзя (`xor bl,bl`). Один байт (`EB 19` → `EB 40`), пишется только при совпадении байтов,
возвращается при остановке модуля и только в изолированном тестовом экземпляре. После этого четыре окна живут спокойно.

Отдельно проверено, что починка не прячет другую беду: с возвращённым исходным байтом экземпляр **не падает и всё равно не
видит лобби** — значит список у него и правда пуст, а патч лишь убрал крэш.

## Что нового в `Enter-IsaacNativeLobby.py`

Windows отдаёт передний план только когда за машиной никто не работает, и проводка окон срывалась на полпути («the game
window is not in front»), оставляя игру на случайном экране. Теперь скрипт умеет продолжать с места:

- начальный экран называется одним из `intro | title | file | menu | online | lobby`, и шаги до него пропускаются;
- роль `wait` — войти в лобби и **не** нажимать «готов»;
- роль `queue` — нажать «готов» из лобби идущего матча (это и ставит игрока в очередь входа);
- сервис по-прежнему сверяется чтением памяти перед каждой клавишей внутри Online, и снимок делается после каждого шага.

## Впуск игрока: проверено вживую

Матч втроём (A — хост, C с задержкой 150 мс и дрожанием 40), четвёртый в лобби, `Adding pending join` у **всех троих**.
Хост прошёл этаж и спустился:

| Что | Итог |
| --- | --- |
| Игра при спуске | **не встала ни у кого**, `Level::Init m_Stage 2`, матч продолжился |
| `NEWCOMERS HELD IN THE LOBBY` | **1 у каждого из троих** — каждый опустошил очередь своим `erase` |
| `newcomers let in / refused` | 0 / 0 |
| `Processing pending joins` в журнале | **нет** — штатный впуск даже не начинался |
| `FAULTS`, `ENEMY UPDATES THROWN` | 0 / 0 у всех |

Это ровно то, что в 0.1.6 вешало матч чёрным экраном: штатный впуск перезагружает `GameState` у всех участников с общего
кадра, а с правилом `gate` счётчики кадров идут порознь. **Страховка 0.1.7 работает.** Настоящий впуск по-прежнему не
сделан — что для него нужно, перечислено в [j460-join-lock-and-pedestals.md](j460-join-lock-and-pedestals.md).

## Помощь тестеру

По просьбе пользователя слово `cheats` стенд даёт **всем** играм и без ключа (`--no-cheats` убирает), но **сами читы
стартуют выключенными**: F6 (свой игрок не получает урона) и F7 (двадцатикратный урон врагам) включаются в том окне,
которое в фокусе, F8 (убить врагов комнаты) — у хоста, чьи это враги. Проверено, что окна независимы: F7, нажатый в одном,
гасит `x20` только там. Удар гостя доходит до хоста сообщением и играется у него **мимо перехвата**, поэтому двадцатикратный
урон считается один раз, а не дважды.

## Что осталось

- Настоящий впуск в идущий матч (пять пунктов из документа 0.1.7); сейчас вошедший ждёт до нового забега.
- Входящий без модуля: он расколет матч, отличать его модуль не умеет.
- Стенд поднимает четвёртого отдельными шагами — стоит свести в один скрипт, когда понадобится чаще.
