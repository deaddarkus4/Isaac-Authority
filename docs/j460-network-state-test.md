# Применение сетевого состояния в одиночном J460

Следующий этап уже выполнен: [настоящая игра-хост и реплика одного игрока во второй игре](j460-game-pair-test.md). Этот документ сохраняет результаты предыдущего теста с отдельным синтетическим отправителем.

19 сентября 2026 реализован отдельный `IsaacAuthorityNetwork.dll`: приём абсолютного положения и скорости выбранного игрока по UDP и применение на проверенном потоке обновления игрока. **Живой сетевой тест прошёл в 19:26 UTC** после подтверждения готовности пользователя.

## Результат живого теста

PID 21580, поток обновления 43720, 96 записанных обновлений. Все пять абсолютных состояний применились по одному разу: `[322,380,0,0]`, `[324,380,0,0]`, `[326,380,0,0]`, `[328,380,0,0]`, `[320,380,0,0]`. Начальное положение `[320,380]` восстановлено последним снимком. Для каждого применения перечитанные float32 совпали с отправленными, следующее обновление сохранило состояние. Дополнительно проверено внешнее чтение памяти игры.

Принято 5 пакетов, отклонено 8; ошибок сети и потерь журнала нет. Исходный слот восстановлен, процесс после проверки отвечает. Восстановление дополнительно проверено внешним чтением: слот `base+0x76bdd0+12` снова содержит `base+0x382af0`. После `Stop` приёмник закрыт, DLL остаётся загруженной до завершения игры. Статус живой проверки записан в установленный `installation.json`.

Артефакты:

- `Binaries/diagnostics/network-state/network-21580-20260919-192621-354447.summary.json`
- `Binaries/diagnostics/network-state/player-step-21580-12518359.jsonl`

Отправителем был отдельный Python-процесс с тестовой последовательностью состояний. Второй игровой клиент и синхронизация мира этим тестом не проверялись.

## Цепочка

`Python test host → UDP 127.0.0.1 → DLL worker → mailbox → player update → readback`

Отправитель передаёт пять абсолютных состояний: X относительно исходного положения +2, +4, +6, +8 и 0; Y исходный, скорости нулевые. Возврат в исходную точку — пятый сетевой снимок. Отправитель добавляет дубликаты, чужую сессию, просроченный и запоздавший снимки. Он является тестовым хостом, а не второй копией Isaac и не симуляцией мира.

Пакеты принимаются отдельным потоком; в игровом вызове нет сетевых операций, файлового вывода и ожидания блокировки. Очередь содержит только один последний снимок, замены учитываются отдельно. Применение выполняется после оригинального обновления игрока; четыре записанных float перечитываются для журнала. Следующее обновление также записывается. Штатная игровая симуляция продолжает работать.

## Ограничения эксперимента

- Оригинальный J460, один локальный игрок и пустой список сетевых устройств. Проверяются указатель игрока, seed его инициализации и указатель комнаты.
- Только loopback. Идентификатор сессии генерируется заново; endpoint отправителя закрепляется первым допустимым снимком. Это разделение локальных тестов, не интернет-аутентификация.
- Номер снимка строго возрастает; старые, повторные, неверные и чужие пакеты отвергаются. Пропуск номера не блокирует дальнейшие снимки.
- Время отправки использует Windows `GetTickCount64` на том же ПК. Возраст ограничен 250 мс и проверяется при приёме и при применении. Сессия принимает коррекции не более 10 секунд; после истечения обработчик перестаёт записывать состояние.
- Игрок должен быть неподвижен: обе компоненты скорости по модулю меньше 0.01. Позиция ограничена X 100..500, Y 100..400; изменение относительно текущей и исходной позиции — не более 16 по каждой оси.
- Обнаруженное изменение игрока/комнаты отключает применение. Полноценный жизненный цикл комнат/сущностей и постоянные сетевые ID не реализованы; проверка указателей не является общей гарантией от повторного использования памяти.
- `Stop` завершает приёмник, восстанавливает слот, дожидается текущего обновления и сохраняет журнал. DLL остаётся загруженной до выхода из игры. Для обновления этой DLL требуется перезапуск игры.

## Формат SNAP v1

Отдельный от 72-байтового AUTH v1 стенда пакет, 64 байта little-endian:

| Смещение | Поле |
| --- | --- |
| 0 | Magic SNAP, u32 `0x50414e53` |
| 4 | Версия u16=1, вид u16=1 |
| 8 | Идентификатор сессии u64 |
| 16 | Epoch u32=1; смена комнаты требует нового запуска |
| 20 | Seed выбранного локального игрока u32 |
| 24 | Возрастающий номер снимка u32, начиная с 1 |
| 28 | Резерв u32=0 |
| 32 | Время отправки `GetTickCount64`, u64 |
| 40 | X, Y, VX, VY — четыре float32 |
| 56 | Два резервных u32=0 |

Описание endpoint публикуется в `%LOCALAPPDATA%\IsaacAuthority\network-PID.json`: port, session, epoch, seed, baseline, deadlineMs. Оно относится только к короткой текущей сессии, не запускает приёмник само по себе.

## Сборка, установка и проверка

```powershell
.\scripts\Build-IsaacAuthority.ps1
.\scripts\Install-IsaacAuthorityNetwork.ps1
$gameProcess = Get-Process isaac-ng
python scripts/Test-IsaacNetworkState.py --pid $gameProcess.Id --binary-directory 'C:\Program Files (x86)\Steam\steamapps\common\The Binding of Isaac Rebirth\IsaacAuthority\Network'
```

Установщик определяет папку через Steam; также поддерживается явный `-GameExecutable`. В подпапку `IsaacAuthority/Network` копируются DLL, attach EXE, тестовый Python-скрипт и read-only считыватель. Установленный скрипт можно запускать напрямую с `--pid`; бинарники он найдёт рядом с собой. Автозапуска нет.

Перед живым тестом нужен одиночный забег, неподвижный персонаж в центре стартовой комнаты, без паузы. Скрипт сначала проверяет доступное состояние, включает модуль, отправляет состояния и независимо перечитывает игру. `Stop` вызывается в `finally`. Затем проверяются точное float32-соответствие всех пяти применений, следующие обновления, один поток, отклонение неверных пакетов, отсутствие потерь журнала и восстановление слота. Неудача также сохраняется в summary и даёт ненулевой exit code.

Журналы DLL: `%LOCALAPPDATA%\IsaacAuthority\logs`. При запуске скрипта из репозитория копии и summary сохраняются в `Binaries/diagnostics/network-state`; у установленного скрипта — в `%LOCALAPPDATA%\IsaacAuthority\verified-network`. Папку можно указать через `--output-directory`.

## Проверено на стенде

MSVC x86 Release, `/W4 /WX`, **6/6 CTest**:

- прежние сетевые инварианты, два UDP-процесса и контракт локального адаптера;
- контракт новой DLL: экспорты и отказ неподдерживаемому EXE;
- формат SNAP, испорченные пакеты, seed/epoch/session, перестановка и дубликаты, устаревание при остановке потребителя, ограничения смещения, привязка endpoint, очередь и перезапуск;
- Python-отправитель и отдельный C++-приёмник: 5 применённых состояний, 8 отклонённых пакетов, возврат к `[300,240,0,0]`.

Живой тест, описанный выше, дополнительно подтвердил доставку и применение ограниченных снимков одного игрока. Отдельный игровой хост, клиентская реплика, передача ввода, настоящая prediction/reconciliation и синхронизация мира остаются следующими этапами.
