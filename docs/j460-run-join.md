# Вход клиента в забег хоста

**20 сентября 2026, 00:18–00:26 UTC.** После [общего сохранения](j460-shared-save.md) у двух игр одинаковые уровни, но клиент всё ещё начинал *свой* забег с тем же seed, введённым вручную. У штатного онлайна клиент получает состояние забега целиком. Здесь то же самое сделано переносом двух файлов, которыми игра пользуется сама, — без единого вызова внутрь игры.

## Носитель состояния уже есть: `gamestate1.dat`

Это файл за пунктом меню «Continue». Формат один у локального профиля и у Steam Cloud (`rep+gamestate1.dat`), заголовок `ISAACNG_GSR0169 `, около 57 КБ. Игра пишет его при **старте забега, смене этажа и выходе в меню** («Exit game»): у HOST и у изолированного экземпляра время записи совпало с последним рестартом забега. Загрузить его игра соглашается только рядом с тем сохранением, с которым он записан (`Cannot load GameState if PersistentData is missing!`).

У двух игр с одним seed и одним сохранением эти файлы одного размера и отличаются в 378 байтах из 57 024 (99 коротких участков — счётчики и подобное). С чистым сохранением другой даже размер.

## Эксперимент

Основная игра не участвовала. В изолированном экземпляре с общим сохранением (окно «SHARED SAVE») создано отличимое состояние — потрачена единственная бомба, — затем штатное «Exit game»: файл переписан (57 118 байт). С копий его `persistentgamedata1.dat` и `gamestate1.dat` запущен четвёртый экземпляр (окно «JOINED»): в меню активен «Continue» с той же карточкой забега (Isaac, Basement I, 00:06:36, hard). Исходный экземпляр продолжен с того же файла. Сравнение чтением памяти:

| | Исходный, продолжен | Вошедший с его файлов | HOST, свежий забег |
| --- | --- | --- | --- |
| Seed / этаж / сложность | `CZH4 8E6W` / 1 / hard | то же | то же |
| Проклятие | Darkness | Darkness | Darkness |
| Комнат, отличных от исходного | — | 0 из 15 | 0 из 15 |
| Посещений стартовой комнаты | 2 | 2 | 1 |
| Сердца / ключи / монеты | 6 и 6 / 0 / 0 | то же | то же |
| **Бомбы** | **0** | **0** | 1 |
| Игровое время | перенесено (счётчик кадров ≈ 12 600) | перенесено (≈ 13 200) | 1 700 |
| Место игрока | у верхней двери (320; 160) | у правой двери (560; 280) | центр (320; 380) |

Состояние забега переносится целиком во всём, что сравнивалось. **Место игрока после «Continue» файлом не задаётся**: игра ставит его у двери, и у двух игр дверь оказалась разной. Это не мешает — положение игроков клиенту всё равно задаёт снимок хоста.

## Вошедший экземпляр в полном конвейере

`Test-IsaacCoop.py --stepped` между двумя изолированными экземплярами, **без рестарта забегов** (клиент остаётся вошедшим в чужой забег). Оба экземпляра не встают на паузу без фокуса, так что основная игра пользователя для этих прогонов не нужна вовсе.

| | Первый прогон | Второй прогон |
| --- | --- | --- |
| Второй игрок | создан в обоих экземплярах — **присоединение в продолженном забеге разрешено** | уже есть |
| Команд принято / снимков применено | 449 из 449 / 405 из 450 | 449 из 449 / 410 из 450 |
| Расхождение после одной и той же команды, максимум | 0,000 на 380 сверках | 0 на 406 сверках |
| Исправления | один телепорт — в самом первом снимке | нет |
| Свой игрок на экране / слово хоста, от клавиши | — | 15 мс / 62 мс |
| В конце, расстояние между играми | 0,0 и 0,0 | 0,0 и 0,0 |
| Итог | **не прошёл** | прошёл |

**Первый прогон не прошёл по критерию теста, а не по поведению модулей.** Свой игрок клиента стоял у своей двери (552,8; 273,1), на хосте он появился у (310; 358) — 257 единиц. Сверка в первом же снимке телепортировала его на место хоста, после чего расхождение было нулевым до конца. Критерий «ни одного телепорта» писался для случая, когда оба стартуют рядом. Теперь телепорт допустим только как **первое выравнивание**; любой более поздний — отказ. Summary сохранён как есть: `predict-20260920-002329-193217`; прошедший — `predict-20260920-002456-550696`.

Слово хоста доходит за 62 мс, а не за 31, как раньше: это четыре шага буфера воспроизведения из [пошагового ввода](j460-impaired-network-test.md). Свой игрок клиент видит через 15 мс.

После прогонов оба экземпляра перезапущены клавишей R; HOST и оба изолированных экземпляра снова совпадают во всём сравниваемом.

## Как пользоваться

```powershell
# сохранение и состояние забега хоста только читаются; копии идут в новый изолированный профиль
.\scripts\Start-IsaacReplica.ps1 -PersistentGameData <persistentgamedata1.dat хоста> -GameState <gamestate1.dat хоста> -WindowPosX 100 -WindowPosY 620
# в новом окне: Enter (заставка), Enter (титул), Space (слот 1), Enter («Continue» уже выбран)
```

Seed вручную больше не вводится: его несёт состояние забега. Меню по-прежнему ведётся помощником с защитой фокуса и снимком окна игры после каждого шага.

## Штатная запись состояния (найдена статически, не вызывалась)

Ghidra, режим `text:`; результаты — `Binaries/research/j460-gamestate-save/`.

| Что | Где |
| --- | --- |
| «Записать состояние забега сейчас» | RVA `0x558ed0`, без аргументов, работает через глобальный `Manager`. Сама проверяет: идёт забег (`Manager+8 == 2`), не daily (`Game+0x26630 == 0`), нет сетевых устройств (`Manager+0x4b3d8`), игрок не мёртв; иначе пишет в журнал `Cannot save game state while not in game` и выходит |
| `Game::SaveState(GameState*)` | RVA `0x2f9000` — её вызывает функция выше. Сигнатура REPENTOGON давала два совпадения (`0x2f9000` и `0x512b60`); верное — первое |
| Объект состояния забега | встроен в `Manager` по смещению `+0xfa4`; имя файла — `Manager+0x20d60`, запись идёт в Steam Cloud или в профиль |
| Второй путь записи | RVA `0x559180`, те же шаги с дополнительными условиями |

## Ограничения и следующий шаг

- **Хост отдаёт состояние только в точках записи** — старт забега, новый этаж, выход в меню. Чтобы клиент вошёл посреди этажа, хосту нужна запись по требованию: вызов `0x558ed0` на потоке игры в безопасной точке. Это первый вызов внутрь игры на этом пути; пробовать его на изолированном экземпляре, со сверкой пролога перед вызовом, и помнить, что у основной игры он перепишет файл в Steam Cloud (то же, что игра делает сама при выходе).
- **Клиент входит через перезапуск экземпляра и меню.** Загрузка состояния в работающую игру — `Game::RestoreState` (RVA `0x2bb790` по сигнатуре REPENTOGON) — не пробовалась.
- Второй игрок в файл состояния не проверялся: файл писался с одним игроком, второго оба экземпляра создавали присоединением уже после входа.
- Сравнивались счётчики игрока, уровень и проклятия; предметы, комнаты с врагами и подбираемое не проверялись.
- Файлы состояния двух игр отличаются в сотнях байт даже при одинаковом забеге; что именно там лежит, не выяснялось.
